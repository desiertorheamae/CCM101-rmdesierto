# Reflection

This laboratory activity provided me with a clearer understanding of how Docker Compose can be used to manage multiple containers as a single application environment. Instead of setting up the Nextcloud application and MariaDB database separately, I was able to define both services in one `docker-compose.yml` file. This made the deployment process more organized because the necessary configurations were placed in one location and could be started together using Docker Compose.

The activity also helped me understand the purpose of a two-tier application architecture in a practical setting. The Nextcloud container served as the web and application tier, while the MariaDB container served as the database tier. Although they had different responsibilities, both services needed to communicate with each other for the application to function properly. Using Docker networking allowed the containers to communicate without requiring the database to be directly exposed to the user.

One of the important concepts I learned was the purpose of the `MYSQL_HOST` environment variable. By setting `MYSQL_HOST=database`, the Nextcloud container was able to identify the MariaDB service using its Docker Compose service name. This helped me understand how containers can locate and communicate with other services within the same Docker network. I also became more familiar with other environment variables, such as `MYSQL_USER`, `MYSQL_PASSWORD`, and `MYSQL_DATABASE`, which provide the necessary database configuration for the application.

I also gained a better understanding of Infrastructure as Code (IaC) through this activity. Instead of relying on several manual commands and configurations, the required deployment settings were written in a structured configuration file. This makes the deployment process easier to organize, repeat, and maintain. The Compose file can also be saved in a GitHub repository, allowing the configuration to be reviewed and reused when needed.

Another lesson from this laboratory was the importance of proper YAML formatting. Since YAML relies on indentation to define the structure of the configuration, even a small formatting mistake can cause Docker Compose to return an error. This taught me to carefully check the spacing, indentation, service names, and environment variables before running the deployment.

This laboratory expanded my understanding of containerized application deployment. I learned that Docker Compose is not only useful for starting multiple containers but also for organizing the relationships and configurations between different services. The activity helped me connect the concepts of Docker, two-tier architecture, networking, and Infrastructure as Code in a practical way. It also gave me a better understanding of how these technologies can be used to create a more organized and manageable cloud deployment environment.
